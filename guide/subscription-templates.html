订阅模板 ​

想让订阅按自己的规则、策略组和 DNS 来，可以用 订阅模板：把自己的 Mihomo、sing-box 或 Surge 配置当骨架，面板只负责把订阅里的节点放进去，其余内容原样下发。网上现成的模板大多可以直接用，不需要再套一层 subconverter。

添加模板 ​

订阅 页右上角点 模板 → 新建模板：

  • 格式：Mihomo、sing-box 或 Surge，一个模板只对应一种格式
  • 内容：
    • 选择规则：下拉快速选择极简、均衡（推荐）、完整或自定义，勾选需要的分类后创建模板
    • 源码编辑：直接粘贴配置，可以随时修改。节点列表留空即可（proxies: []），面板会填进去
    • 从网址获取：填模板地址（例如 GitHub 上的 raw 链接），面板每天下载一次，下载失败继续用上次的内容。网址模板不能直接改，点 复制为本地模板 得到一份可编辑的副本
  • 插入分组：点 🇭🇰 香港、🇯🇵 日本等按钮，在合适的位置插入一个按地区自动收节点的测速组；记得在“节点选择”之类的组里引用它
  • 用示例开始：内容为空时可以用一份最小的示例起步
  • 检查：检查格式，并用某个订阅的节点预演每个策略组能收到哪些节点；没有节点的组标为“空组”

选择规则创建模板 ​

默认使用 均衡规则，选中私有网络、AI、GitHub、YouTube、Telegram、Google、国内服务、非中国 8 个类别；极简规则 只选私有网络、国内服务、非中国，完整规则 选中全部 19 类。单独勾选或取消分类后会切换为 自定义，切换预设会保留额外添加的自定义规则。

  • 规则去向与顺序：为每条规则选择节点选择、某个策略组、直连或拦截，用上下箭头调整优先级。从上往下匹配，第一条命中后生效；具体服务应放在包含它的大类前面。
  • 添加自定义规则：支持完整域名、域名后缀、域名关键词和 IPv4 / IPv6 CIDR。域名不带协议、路径或通配符，例如 example.com；CIDR 如 192.0.2.0/24、2001:db8::/32。新规则放在最前面，仍可调整顺序。
  • 策略组：默认只提供自动选择测速组；香港、日本、美国等地区组可按需快捷添加，可修改名称和节点名称正则，或添加、删除分组。删除分组后，原来指向它的规则会回到“节点选择”。
  • 兜底去向：没有任何规则命中的流量走这里。
  • 生成并预览：按顺序查看每条规则的分流去向，代理节点详情可折叠展开，也可查看生成的配置；保存后可重新打开继续勾选编辑，再到订阅的“规则”页选用。

选择规则生成的 sing-box 模板支持 1.12+ 客户端；Mihomo 模板的规则集用 YAML 格式，Stash 和 Shadowrocket 选用同一个模板也能读。规则集沿用 MetaCubeX / blackmatrix7，客户端按天更新；面板无需增加服务。保存时生成配置，之后改了规则要重新保存才会更新。切到“源码编辑”会先生成当前配置，手动修改并保存后改为源码模板；已有任意源码不会自动反向转换为规则选择。

节点怎么进策略组 ​

按各客户端本来就支持的写法，模板里写好，面板不改：

格式写法说明
Mihomoinclude-all: true，可加 filter: "(?i)港|HK"、exclude-filter客户端自己按 filter 收节点；多个表达式用 ` 分隔
sing-box"outbounds": ["{all}"]，可加 "filter": [{"action": "include", "keywords": ["港|HK"]}]面板把 {all} 换成符合 filter 的节点名（sing-box-subscribe 的写法）；action 为 exclude 时排除；组里一个节点都没有时换成 direct，避免 sing-box 报错
Surgeinclude-all-proxies=1，可加 policy-regex-filter=港|HK客户端自己按正则收节点

例如 Mihomo：

yaml
proxies: [] # 面板填入订阅里的节点
proxy-groups:
  - name: 🚀 节点选择
    type: select
    proxies: [🇭🇰 香港, DIRECT]
  - name: 🇭🇰 香港
    type: url-test
    include-all: true
    filter: "(?i)港|HK|Hong Kong"
rules:
  - GEOIP,CN,DIRECT
  - MATCH,🚀 节点选择

面板在生成配置时：

  • Mihomo：只替换 proxies 这一段，模板的其余文字（包括注释和顺序）原样保留
  • sing-box：节点加在 outbounds 末尾，WireGuard 节点放进 endpoints
  • Surge：节点写在 [Proxy] 段原有内容之后；没有 [Proxy] 段时自动加上
  • 开了 链式代理 时，自动加上“落地节点”“中转节点”两个组
  • 节点名和模板里的组名重复时，节点名后面加 #2

在订阅里使用 ​

编辑订阅 → 规则 → 订阅模板，Mihomo、sing-box、Surge、Stash、Shadowrocket 各选一个模板：

  • 选了模板的客户端拿到按模板生成的配置，下面的 内置分组与规则 对它不生效
  • 没选模板的客户端照旧用内置规则；Loon、Quantumult X 暂不支持模板
  • Stash 没单独选模板时，沿用 Mihomo 的模板；Mihomo 模板里有 mrs 规则集（Stash 读不了）时不沿用，改用内置规则
  • Stash、Shadowrocket 用 Mihomo 格式的模板，可以和 Mihomo 共用同一个：
    • 这两个客户端不一定认 include-all / filter，面板会把这类组展开成具体的节点列表（模板里原本写的成员排在前面），一个节点都匹配不到时放一个 DIRECT，避免客户端报空组
    • 展开时和 Mihomo 收节点的规则一致：filter 支持 (?!...)、(?<!...) 这类前后断言（如“其他地区”常用的 ^(?!.*(港|日|美)).*$），exclude-type 按协议排除（如 Shadowsocks|Http），用 YAML 锚点 <<: *xxx 继承来的 include-all、filter 也会生效
    • 规则集要用 yaml 或 text 格式：mrs 只有 Mihomo 能读，模板检查时会提醒
    • Shadowrocket 开了链式代理时，落地节点按中转各复制一份（“落地（经 中转）”），和不用模板时一样
    • Shadowrocket 选了模板后下发的是完整配置，订阅详情里的 Shadowrocket 按钮会改为导入配置
  • 筛选、改名、加国旗、去重和脚本照常先执行，处理后的节点才放进模板
  • 预览 页的 模板策略组 里能看到每个组收到了哪些节点

有订阅在用的模板不能删除，也不能改格式；先在订阅里换掉。备份会包含模板。

按服务独立选择节点 ​

规则编辑器默认开启“按服务生成独立策略组”。每个已选分类和“漏网之鱼”各生成一个选择组，可在客户端分别选择节点、节点分组或直连。类别的规则去向是该组的默认选择。sing-box 的拦截类别使用原生拒绝动作。关闭此选项则直接按规则去向转发。
