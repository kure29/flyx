通知 ​

在 设置 → 通知 里填写 Telegram 机器人或 Webhook 地址（两个都填就都发），打开 启用通知 后保存。点 发送测试 可以先用当前填写的内容试发一条，不用先保存。

事件 ​

事件什么时候提醒
服务器掉线 / 恢复服务器断开超过 90 秒才提醒，重启、升级等短暂断线不打扰；重新连上后再发一条恢复
节点连不上 / 恢复连通性检测 连续两次失败（约 6 分钟）才提醒，恢复后再发一条
延迟 / 丢包异常某个 测试点 连续 3 次（约 9 分钟）超过阈值才提醒，恢复时也通知
回程线路变化每天检测 回程 时对比上一次，例如 CN2 GIA 变成 163
内核运行出错服务器上的 Xray / sing-box / Snell 状态变成出错时提醒，附带错误信息
服务器即将到期服务器设置了到期时间，到期前 3 天内提醒一次（在服务器页关掉到期提醒的服务器不会提醒）
用户流量 / 到期转发用户流量用到 90%、用完，或 3 天内到期；订阅 流量用到 90%、用完，或 3 天内到期
Gist 备份失败自动上传到 GitHub Gist 失败时提醒，附带原因
每日汇总每天在设定的时间发一条：服务器在线数、内核出错数、节点连不上的数量、入站和转发流量、分享订阅情况

同一个问题只提醒一次，恢复后才会再次提醒。不想收的事件取消勾选即可。

延迟 / 丢包阈值 同时用于全局及单台服务器独立开启的通知：

  • 丢包超过：默认 20%
  • 延迟超过（可选）：留空不按延迟提醒，只看丢包

每日汇总默认早上 9 点发送，可以在 每日汇总发送时间 里改（0–23 点）。时间按面板服务器的时区，安装脚本默认 Asia/Shanghai。

按服务器设置 ​

在 服务器 → 编辑 → 通知设置 中，可以分别设置这台服务器的掉线 / 恢复、节点连通性、延迟 / 丢包、回程线路变化、内核错误和到期通知：

  • 跟随全局：默认选项，沿用「设置 → 通知」中的事件选择。
  • 开启：为这台服务器开启该事件，即使全局未勾选该事件。
  • 关闭：只关闭这台服务器的该事件，其他服务器不受影响。

例如，不需要某台服务器的延迟检测超时通知时，将它的 延迟 / 丢包异常 设为 关闭 后保存即可。该服务器的超时、延迟、丢包异常和恢复通知都会关闭，检测及历史图表仍正常保留。

所有服务器仍共用全局推送渠道，并受 启用通知 总开关控制。用户流量 / 到期、Gist 备份失败和每日汇总属于面板事件，仍在全局设置中配置。服务器的通知设置会随 JSON 备份导出和恢复。

Telegram ​

  1. 找 @BotFather 发 /newbot 创建机器人，拿到 Bot Token（形如 123456:ABC-DEF...）
  2. 给你的机器人发一条消息（或把它拉进群），再用 @userinfobot 查自己的 Chat ID；群组的 ID 以 -100 开头
  3. 填入面板，点 发送测试

面板服务器在国内、连不上 api.telegram.org 时，可以在 Telegram API 地址 里填一个反代地址（例如 Cloudflare Workers 反代），面板会请求 <地址>/bot<Token>/sendMessage。

Webhook ​

面板会向填写的地址发送 POST 请求，内容是 JSON：

json
{
  "event": "node_offline",
  "title": "节点掉线",
  "message": "节点：东京-1",
  "text": "[FLYX] 节点掉线\n节点：东京-1\n时间：2026-10-16 10:00:00 UTC",
  "time": 1792130385331,
  "app": "FLYX"
}

  • event：

    值事件
    node_offline服务器掉线 / 恢复
    inbound_down节点连不上 / 恢复
    latency_bad延迟 / 丢包异常、恢复
    route_change回程线路变化
    kernel_error内核运行出错
    node_expiry服务器即将到期
    user_quota用户流量 / 到期
    backup_failedGist 备份失败
    daily_report每日汇总
    test测试消息

  • text：拼好的完整文本，直接转发给企业微信、钉钉、Bark、Server 酱等服务时用它即可

  • 返回 2xx 视为发送成功

Bot Token 和 Webhook 地址只有管理员能看到，也不会写进 JSON 备份。
