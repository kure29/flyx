隧道与转发规则 ​

面板保留了原来转发面板的隧道和转发规则。只做落地 + 中转的话，用 对接中转 就够了，面板会自动建好需要的转发规则；需要自己管理端口转发时再看这一页。

FLYX 是单用户面板：只有管理员一个账号，没有多用户、用户配额、限速和流量计费。

隧道 ​

中转 → 隧道：从入口服务器到出口的转发线路，转发规则建在隧道上。

设置说明
隧道类型端口转发：入口服务器直接转发到目标；隧道转发：入口经加密隧道到出口服务器，再由出口转发（入口和出口不能是同一台服务器）
入口服务器可以多选；多台服务器时可选 负载策略
协议隧道转发时入口和出口之间用的协议；只要中转、不需要加密时选 TCP
转发引擎端口转发时可选。面板转发（默认）：agent 直接转发；realm：入口服务器自动安装 realm 来跑这条隧道的转发

隧道卡片上的 诊断 可以检查入口到出口是否连通。

规则的流量按实际上传和下载字节统计，面板转发、realm 和 nftables 都一样。旧版本隧道上设置的计费方向和流量倍率不再生效，保存隧道时会被清除。

realm 引擎 ​

realm 是 Rust 写的端口转发程序，占用低，适合流量大的纯端口转发。选了 realm 的隧道：

  • 入口服务器上的 realm 由面板安装和管理（入站 → 内核 里能看到“realm（转发引擎）”，可查看日志），agent 需要升级到支持 realm 的版本
  • 转发规则照常建，TCP / UDP、多个目标负载（轮询或 IP 哈希，主备和随机按轮询处理）、Proxy Protocol 都支持；流量照常统计，暂停也照常生效
  • 不能用于 nftables 模式服务器和远程服务器

随时可以在编辑隧道时切换引擎，面板会把已有的转发规则迁移过去。

转发规则 ​

规则 页（或 中转 → 规则）：把入口端口收到的流量经隧道转发到目标地址。

  • 选 所属隧道，填 落地地址（目标地址和端口），入口端口留空自动分配
  • 支持 TCP / UDP
  • 高级设置里可以开启 Proxy Protocol 发送 / 接收，让目标看到客户端真实 IP
  • 支持批量导入导出

旧版本规则上设置的限速、最大连接数和每 IP 限制不再下发到服务器；节点上留下的限速器会在下次同步配置时清理，编辑保存规则时这些旧值也会被清除。

监控 ​

监控已并入 服务器 和 中转：

  • 服务器 列表（和卡片）上直接显示每台服务器的 CPU、内存、磁盘、实时网速和本月流量；点服务器再点 监控，看这台服务器的历史曲线和服务监控。本月流量从升级到这个版本后开始累计，按浏览器所在时区从每月 1 号算起
  • 中转 → 质量：隧道的延迟和丢包

节点历史的新记录按 15 分钟汇总；半小时、45 分钟时区的月初边界可正确划分。跨月的旧小时记录只能按时长估算，相关提示会显示在本月流量的说明中。

节点流量汇总仍保留 400 天，不因粒度变化缩短历史。连续采集时，每个节点每天的汇总记录由 24 条增至 96 条，400 天约 38,400 条；汇总表及其索引的存储需求会随记录数增长，实际占用取决于采集情况和数据库。这不表示整个数据库会增大四倍，升级前应按节点数量预留空间。

监控明细的保留天数在 设置 → 服务器与监控 里设置，不影响上述流量汇总的 400 天保留期。服务器到各地运营商的延迟见 延迟与回程。

共享 ​

共享 页：把本地服务器分享给其他 FLYX 面板，或导入别人分享的服务器，两个面板可以互相使用对方的服务器做转发。
