基本概念 ​

FLYX 由一个 面板 和装在各台服务器上的 agent 组成：面板负责配置和展示，agent 负责在服务器上执行。先弄清下面几个词，后面的文档会好读很多。

整体结构 ​

txt
客户端 ──► 中转服务器（前置 / IX）──► 节点（服务器上的 Xray / sing-box / Snell 入站）──► 网站
               ▲                          ▲
               └──────── agent ───────────┘
                           ▲
                     面板（Web 界面 + 后端）
名词是什么在面板哪里
面板Web 界面和后端，用 Docker 部署在一台服务器上—
服务器装了 agent、连上面板的机器，可以搭节点，也可以当中转服务器 页
内核服务器上真正跑代理协议的程序：Xray、sing-box 或 Snell服务器 → 内核
节点客户端能连上的一个代理：自建的入站、导入的节点、订阅源里的节点节点 页
入站自建的节点：内核上的一个代理服务（协议 + 端口 + 凭据）节点 → 入站
导入的节点不是面板搭的现成节点（脚本搭的、机场的），只用来接中转、进订阅节点 → 更多 → 导入节点
隧道从入口服务器到出口服务器的转发线路中转 → 隧道
中转线路把某条隧道接到某个节点上，客户端先连中转再到节点中转 → 线路
转发规则传统的端口转发：入口端口收到的流量转到目标地址规则 页
节点组从节点和订阅源里挑选、筛选、改名后的一份节点列表，多个订阅可以共用订阅 → 节点组
订阅一个链接，包含选中节点组里的节点和它们的中转线路，客户端导入即用订阅 页

节点和中转 ​

  • 节点：客户端最终连到的代理，网站看到的是节点的 IP。可以在自己的服务器上搭（装内核、建入站），也可以导入现成的节点
  • 中转：客户端和节点之间的跳板，用来改善线路（比如国内前置 → IX → 海外节点），本身不跑代理协议，只转发流量

一台服务器可以同时搭节点和当中转。

「落地」是什么

「落地」只用在 链式代理 里，表示角色：客户端先连 中转节点，再经它连 落地节点 出去。它说的是节点在这条链里的位置，不是另一类东西。

一条线路怎么搭起来 ​

  1. 安装面板，在 设置 里填好“面板后端地址”
  2. 安装 agent：在要用的服务器上运行面板生成的安装命令
  3. 搭建节点：给服务器装内核、建入站
  4. 对接中转（可选）：建隧道，把它接到节点上
  5. 订阅：建节点组，再把节点和中转线路一起导入客户端
