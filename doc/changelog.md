# 更新日志

每个版本的主要变化。**升级** 一行说明除了面板以外还要不要升级节点 agent；没写的只需升级面板，见 [升级](./guide/upgrade.md)。

## 3.9.1

2026-11-07

- **服务器地区**：面板按服务器地址（IPv4、域名或 IPv6）自动识别所在国家，**服务器** 列表名称前显示国旗；识别不对时在 **服务器 → 编辑 → 地区** 手动选择。识别用 [DB-IP](https://db-ip.com) 免费国家库，面板自动下载到数据目录并每月更新，只在本地查询，不会把服务器地址发给第三方；环境变量 `GEOIP_COUNTRY_DB` 可以改用自己的数据库或设为 `off` 关闭。见 [状态页 → 地区](./guide/status-page.md#地区)
- **状态页按地区显示**：状态页用识别出（或手动选择）的地区显示国旗、按地区筛选，服务器名不用再带国旗 emoji；公开接口新增 `region`（只有国家代码，不含地址），主题可以读取，见 [状态页主题开发](./guide/status-theme-dev.md)
- JSON 备份包含手动选择的地区

## 3.9.0

2026-11-07

- **状态页默认主题重新设计**：改为 shadcn/ui 风格的小卡片，顶部是离线提醒和在线、带宽、流量、可用率四个数字；卡片上显示 CPU / 内存 / Swap / 磁盘、网速、本月流量、TCP / UDP 连接数和进程数、负载、各测试点延迟和 30 天可用率，整张卡片点进去就是服务器详情。可以切换成列表（表格）显示、按名称筛选，右上角切换深色 / 浅色。见 [状态页](./guide/status-page.md)

- **服务器详情页重新设计**：新增当前状态一栏和「延迟与回程」，图表改为渐变面积图
- **仓库仍在 kure29/flyx**：项目曾短暂迁到 `seren233/flyx`，现已改回 [kure29/flyx](https://github.com/kure29/flyx)，文档仍是 <https://kure29.github.io/flyx/>，镜像仍是 `ghcr.io/kure29/…`。那段时间从 `seren233` 装的面板和节点，用 kure29 的安装脚本重新运行一次更新即可，脚本和 Docker 安装命令认得 `ghcr.io/seren233/` 的镜像
- **状态页服务器详情**：点状态页上的服务器进入详情页，可以看近 1 小时、6 小时、24 小时、7 天的 CPU / 内存 / Swap / 磁盘、网速、负载、连接数与进程数，以及各测试点延迟的历史图表。见 [状态页 → 服务器详情](./guide/status-page.md#服务器详情)
- **agent 上报更多信息**：节点 agent 会上报 Swap、进程数，以及系统、内核、架构、CPU 型号和虚拟化方式（可识别 KVM、LXC、OpenVZ、Docker 等）。服务器列表的说明行显示系统和虚拟化方式，悬停可见完整信息；状态页卡片显示 Swap 和进程数
- **状态页可显示系统信息**：**设置** → **状态页** 新增 **显示系统信息**（默认关闭），开启后显示系统、架构、虚拟化方式和 CPU 型号，内核版本始终不公开
- **主题设置**：主题可以在 `theme.json` 里声明设置项（格式与 monitor 主题相同），**设置** → **状态页** → **主题** 卡片上会出现 **设置**，按声明生成表单，只保存改过的项，可一键恢复默认。见 [状态页 → 主题](./guide/status-page.md#主题)
- **主题开发**：新增公开的历史接口和主题设置接口，主题可以画历史图表、读取自己的设置，见 [状态页主题开发](./guide/status-theme-dev.md)
- **升级**：面板和节点 agent 都要升级（3.8.0 没有单独发布，它的更新都在本版本里）。agent 不升级也能正常工作，只是没有 Swap、进程数和系统信息

- **显示核心数和容量**：agent 会上报 CPU 核心数、内存和磁盘的已用 / 总量，状态页显示「N 核」「已用 / 总量」，服务器列表悬停可见
- **升级**：面板和节点 agent 都要升级。agent 不升级也能正常工作，只是不显示核心数和内存、磁盘容量

## 3.5.6

2026-11-05

- **修复容器服务器上订阅节点无法使用**：在 LXC、OpenVZ 等没有 nftables 权限的服务器上，单独分享的节点能用，但加入订阅后连不上（延迟显示 -1，内核日志报「dial tcp …: operation not permitted」）。原因是订阅用户的流量会单独打上标记用于按用户统计，而这类服务器不允许打标记。现在面板检测到服务器没有 nftables 权限时，订阅用户直接走默认出口，不再打标记；升级面板后，这类服务器的内核配置会自动重新下发，不用手动操作。这类服务器本来就无法按用户统计流量，功能上没有损失
- **普通用户添加转发时可以选择监听 IP**：之前普通用户选好隧道后，「监听 IP」下拉框是灰的，提示「当前隧道入口服务器暂无可选 IP」，端口范围提示也不显示。现在会列出该隧道入口服务器的 IP（与管理员看到的一致），端口范围也会显示；提交时只接受这些地址，避免选了服务器上不存在的地址导致转发监听失败
- **升级**：只需升级面板

## 3.5.5

2026-11-05

- **修复 Alpine 等系统上 sing-box 内核无法启动**：sing-box 1.13 起官方默认的 Linux 安装包依赖 glibc，在 Alpine 等 musl 系统上安装后会报「进程退出: fork/exec …/sing-box: no such file or directory」。现在 1.13 及以后的版本（包括 latest）改为下载静态编译的 musl 版本，任何 Linux 都能运行；32 位 x86 和 ARMv7 服务器也能正常安装了
- **装坏的内核会自动重装**：节点 agent 会检查已安装的内核文件能否在本机运行（CPU 架构、需要的系统组件是否齐全），不能运行就自动删除并重新下载，日志里会说明原因。上面那种 Alpine 上装坏的 sing-box，升级 agent 后会自动修好，不用再手动删除内核
- **批量添加转发失败时不再占用端口**：一次添加多条转发，其中一条失败时，已经打开的端口会被释放，重试不会再报端口已被占用
- **容器服务器的 nftables 提示更清楚**：在 LXC、OpenVZ 等没有 nftables 权限的服务器上，日志会说明是权限原因，同样的错误只记一次；入站的「仅允许中转机访问（防火墙白名单）」开关会显示原因并禁止开启，避免开启后入站被停止
- **暂停的中转不再悄悄消失**：中转对应的转发暂停或被删除时，中转列表会说明它不会出现在订阅中，订阅预览也会列出没有包含的中转
- **升级**：先升级面板，再把节点 agent 升级到 3.5.5（内核自动重装、端口释放和 nftables 提示需要新版 agent；sing-box 下载修复只需升级面板）

## 3.5.4

2026-11-04

- **节点重启后不再因端口冲突整体启动失败**：节点 agent 启动时如果某条规则的端口被占用（被其他程序占用，或有重复的规则），只跳过这一条并记录日志，其余规则照常启动，节点保持在线，可以在面板上修改或删除这条规则。之前会导致 agent 反复重启失败、面板显示节点离线
- **中转的订阅地址更不容易填错**：中转的「分享地址」改名为「订阅地址（可选）」，并说明应填中转入口服务器的地址或域名；填了的话，中转列表会显示订阅实际使用的地址。填成落地节点自己的地址时会提示并拒绝保存，避免订阅里的节点绕过中转直连落地机
- **升级**：端口冲突的修复需要把节点 agent 升级到 3.5.4

## 3.4.2

2026-10-30

- **删除服务器时可同时卸载 agent**：删除服务器（单个或批量）的确认窗口新增 **同时卸载服务器上的 agent**，默认勾选。会停止内核、删除 agent 建的 nftables 规则、恢复调优前的系统参数，脚本安装的还会删除服务和安装目录；nftables 转发的服务器会通过 SSH 清除转发规则。服务器离线时，等它下次连上面板再自动卸载。Docker 安装的 agent 会清空配置并停止连接面板，容器需要手动删除。只想把服务器换到另一个面板时取消勾选即可，见 [删除服务器并卸载 agent](./guide/agent.md#删除服务器并卸载-agent)

- **升级**：删除服务器时自动卸载需要把节点 agent 升级到 3.4.2；旧 agent 会提示版本过旧，需在服务器上手动卸载

## 3.4.0

2026-10-28

- **项目统一改名为 FLYX**：镜像、安装目录、服务名、环境变量统一用 FLYX，新装的面板和节点用新名字（节点 `flyx-agent`、`/etc/flyx-agent`）。已有部署升级时继续用原来的容器、数据卷和目录，数据和流量计数都不受影响。回退到 3.3.x 时要按文档处理镜像名，见 [FLYX 命名兼容](./guide/upgrade.md#flyx-命名兼容)
- **流量上报不再丢、不再重复计**：节点会先把待上报的流量存到本地，面板确认入账后才删除；网络中断、面板重启时会自动重试，重复提交也不会重复扣费。服务关闭前最后一段流量也会补报。面板数据库从备份恢复后，节点会自动重新建立上报，见 [流量可靠上报](./guide/upgrade.md#流量可靠上报)
- **单向 / 双向计费按选项计算**：隧道的计费方式以前被当成倍数，单向实际按上传 + 下载计、双向再乘 2。现在单向只计上传，双向计上传 + 下载，流量倍率单独生效。**升级后大部分用户的扣费会变少**；已经用掉的流量不会重算。联邦隧道上的转发不再计入本地用户的额度，只计入共享节点
- **配额更可靠**：普通用户不能再重置自己或别人的流量配额；额度用完后暂停失败会自动重试，nftables 转发暂停时连已建立的连接也会断开；面板在重置日停机，开机后会补做月度重置，29 / 30 / 31 号重置在短月份按月末处理；用户到期后一分钟内停用
- **登录验证码不能再被绕过**：启用验证码后，所有密码登录都要通过验证码，包括 WHMCS 等集成。依赖原来请求头豁免的集成需要改为走验证码流程，见 [常见问题](./guide/faq.md)
- **白名单出错时不再放行**：开了入站白名单的内核，在节点缺少 nftables 或规则同步失败时会停止并报错，不再无保护地运行；修好节点的 nftables 后重新启动内核即可
- **Docker 节点不再被 core 文件写满磁盘**：旧版节点镜像里的 nftables 在较新的系统内核上会崩溃，每分钟在数据目录留下一个几 MB 的 `core` 文件。现在节点读取流量计数不再触发这个问题，启动时会自动清理已有的 core 文件，节点镜像也升级到了 Debian 13（nftables 1.1）
- **流量统计按 15 分钟记录**：节点和订阅流量改为每 15 分钟记一条，印度（+5:30）、尼泊尔（+5:45）等非整点时区的日、月统计能正确划分；升级前的整点记录跨日、跨月时按时长估算并标注。保留时间不变，但记录数约为原来的 4 倍，节点和订阅多的面板请预留数据库空间
- **订阅和用户更稳**：订阅源部分节点解析失败时，不再删掉旧节点和它们在节点组里的引用；订阅停用 / 恢复下发失败会继续重试；删除用户时会同时清掉节点上该用户的 realm 转发
- **页面更流畅**：节点多时列表不再整页重绘，后台标签页暂停轮询，切换节点或时间范围时旧数据不会再覆盖新数据，服务监控历史有了上限
- **升级**：**先升级面板，再升级节点 agent**。流量可靠上报、白名单保护和 core 文件修复都需要把节点 agent 升级到 3.4.0；想换用新版 nftables 的 Docker 节点需要重新拉取镜像并重建容器
