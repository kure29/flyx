# 更新日志

每个版本的主要变化。**升级** 一行说明除了面板以外还要不要升级节点 agent；没写的只需升级面板，见 [升级](./guide/upgrade.md)。

完整的提交记录见 [GitHub Releases](https://github.com/kure29/flyx/releases)。

## 3.4.3

2026-10-30

- **可以和 flux-panel / FLVX 装在同一台服务器**：以前安装脚本看到 `flux-panel-backend` 容器、`/etc/flux_agent` 目录或 `flux_agent` 容器就当成自己的旧安装接管，还会删除 flux-panel 原版的 `gost.service`。现在只有确认是 FLYX 自己的旧安装才沿用（面板和 Docker 节点看镜像是否来自本项目，脚本节点看 `config.json` 里的面板地址），其他面板的安装不会被接管、改写或删除，见 [和 flux-panel / FLVX 装在同一台服务器](./guide/upgrade.md#和-flux-panel-flvx-装在同一台服务器)
- **面板新安装放到 `/opt/flyx-panel`**：不再把 `.env` 和 `docker-compose.yml` 写到当前目录（常见为 `/root`），避免覆盖其他面板的文件；默认端口 `6366` / `6365` 被占用时会建议下一个空闲端口。已有部署不受影响，更新、卸载、迁移 PostgreSQL 只会处理 FLYX 的部署
- **nftables 转发不再碰 FLVX 的表**：升级前已配置的 nftables 服务器照常沿用原来的表；之后新添加的服务器只使用 `flyx` 表

## 3.4.2

2026-10-30

- **删除服务器时可同时卸载 agent**：删除服务器（单个或批量）的确认窗口新增 **同时卸载服务器上的 agent**，默认勾选。会停止内核、删除 agent 建的 nftables 规则、恢复调优前的系统参数，脚本安装的还会删除服务和安装目录；nftables 转发的服务器会通过 SSH 清除转发规则。服务器离线时，等它下次连上面板再自动卸载。Docker 安装的 agent 会清空配置并停止连接面板，容器需要手动删除。只想把服务器换到另一个面板时取消勾选即可，见 [删除服务器并卸载 agent](./guide/agent.md#删除服务器并卸载-agent)
- **节点支持 Docker Compose 安装**：服务器的安装命令窗口新增 **Docker Compose** 方式，Compose 文件写入 `/opt/docker/flyx-agent/`；Docker 和 Docker Compose 方式都可以打开 **服务器调优** 开关（以 `--privileged` 运行），见 [用 Docker Compose 安装](./guide/agent.md#用-docker-compose-安装)
- **Mihomo 订阅启用抗量子密钥交换**：服务器装的是 Xray 25.5.16 及以上时，Mihomo 订阅里的 VLESS Reality 节点会带上 `support-x25519mlkem768: true`；sing-box、旧版 Xray 和导入的节点不受影响，见 [常见问题](./guide/faq.md#reality-用-clash-mihomo-连不上)
- **升级**：删除服务器时自动卸载需要把节点 agent 升级到 3.4.2；旧 agent 会提示版本过旧，需在服务器上手动卸载

## 3.4.1

2026-10-28

- **修复升级到 3.4.0 失败、面板打不开（502）**：3.4.0 改了 Compose 文件里网络的写法，从旧版本在面板内升级时，Docker Compose 会报 `network gost-network was found but has incorrect label`，升级失败；用脚本升级后也可能出现前端没有启动、访问面板返回 502 的情况。3.4.1 改回原来的写法，面板内升级和脚本升级都能正常完成。3.4.0 期间新装的面板升级时，会自动停止服务并重建网络，数据不受影响
- **已经卡在 3.4.0 的面板**：直接在面板内升级或用脚本升级到 3.4.1 即可。如果面板打不开，在面板服务器上进入存放 `docker-compose.yml` 的目录（常见为 `/root`），执行 `docker compose up -d` 启动前端，再升级

## 3.4.0

2026-10-28

- **项目统一改名为 FLYX**：镜像、安装目录、服务名、环境变量统一用 FLYX，新装的面板和节点用新名字（节点 `flyx-agent`、`/etc/flyx-agent`）。已有部署升级时继续用原来的容器、数据卷和目录，数据和流量计数都不受影响。回退到 3.3.x 时要按文档处理镜像名，见 [FLYX 命名兼容](./guide/upgrade.md#flyx-命名兼容)
- **流量上报不再丢、不再重复计**：节点会先把待上报的流量存到本地，面板确认入账后才删除；网络中断、面板重启时会自动重试，重复提交也不会重复扣费。服务关闭前最后一段流量也会补报。面板数据库从备份恢复后，节点会自动重新建立上报，见 [流量可靠上报](./guide/upgrade.md#流量可靠上报)
- **单向 / 双向计费按选项计算**：隧道的计费方式以前被当成倍数，单向实际按上传 + 下载计、双向再乘 2。现在单向只计上传，双向计上传 + 下载，流量倍率单独生效。**升级后大部分用户的扣费会变少**；已经用掉的流量不会重算。联邦隧道上的转发不再计入本地用户的额度，只计入共享节点
- **配额更可靠**：普通用户不能再重置自己或别人的流量配额；额度用完后暂停失败会自动重试，nftables 转发暂停时连已建立的连接也会断开；面板在重置日停机，开机后会补做月度重置，29 / 30 / 31 号重置在短月份按月末处理；用户到期后一分钟内停用
- **登录验证码不能再被绕过**：启用验证码后，所有密码登录都要通过验证码，包括 WHMCS 等集成。依赖原来请求头豁免的集成需要改为走验证码流程，见 [常见问题](./guide/faq.md)
- **白名单出错时不再放行**：开了入站白名单的内核，在节点缺少 nftables 或规则同步失败时会停止并报错，不再无保护地运行；修好节点的 nftables 后重新启动内核即可
- **Docker 节点不再被 core 文件写满磁盘**：旧版节点镜像里的 nftables 在较新的系统内核上会崩溃，每分钟在数据目录留下一个几 MB 的 `core` 文件。现在节点读取流量计数不再触发这个问题，启动时会自动清理已有的 core 文件，节点镜像也升级到了 Debian 13（nftables 1.1）
- **流量统计按 15 分钟记录**：节点和订阅流量改为每 15 分钟记一条，印度（+5:30）、尼泊尔（+5:45）等非整点时区的日、月统计能正确划分；升级前的整点记录跨日、跨月时按时长估算并标注。保留时间不变，但记录数约为原来的 4 倍，节点和订阅多的面板请预留数据库空间
- **订阅和用户更稳**：订阅源部分节点解析失败时，不再删掉旧节点和它们在节点组里的引用；订阅停用 / 恢复下发失败会继续重试；删除用户时会同时清掉节点上该用户的 realm 转发
- **页面更流畅**：节点多时列表不再整页重绘，后台标签页暂停轮询，切换节点或时间范围时旧数据不会再覆盖新数据，服务监控历史有了上限
- **升级**：**先升级面板，再升级节点 agent**。流量可靠上报、白名单保护和 core 文件修复都需要把节点 agent 升级到 3.4.0；想换用新版 nftables 的 Docker 节点需要重新拉取镜像并重建容器

## 3.3.45

2026-10-27

- **服务器页更流畅**：服务器多的时候，每台服务器的实时数据一到，整个列表就重新渲染一次，手机上滚动会卡。现在实时数据合并处理，最多每秒刷新一次，滚动不再卡顿
- **不再反复提示“监控连接中”**：刷新或切换页面时，服务器页不再先闪一下黄色的“监控连接中...”。各页面共用一条实时连接，切回服务器页直接复用；只有连接超过 2 秒还没建立，或者中途断线，才会提示
- **服务器离线时内核显示“服务器离线”**：服务器重装系统或掉线后，内核和节点列表以前还显示重装前的“运行中”，现在显示“服务器离线”。agent 重新连上后，面板会自动把内核装回去并恢复节点；内核下载较慢时也不会再被误标为异常
- **标签多时节点名不再被挤掉**：节点打了很多标签后，手机上节点名会看不见，标签还会盖住开关。现在标签放不下就换行，列表里最多显示 3 个，其余折叠成“+N”
- **面板检查新版本更可靠**：**设置 → 系统与升级** 里「最新版本」有时一直显示「未获取到可用版本」，是因为查询 GitHub 的次数用完了。现在会使用缓存，失败时换其他途径再查；实在查不到会显示原因。经常遇到的话，可以给面板设置 `GITHUB_TOKEN`
- **服务器调优窗口加回关闭按钮**：调优窗口底部重新有了 **关闭** 按钮。关闭窗口不会停止调优任务，要中止任务请用 **停止任务**

## 3.3.44

2026-10-27

- **手动填写节点**：导入节点不再只能粘贴分享链接或订阅。在 **导入节点** 窗口顶部切到 **手动填写**，选好协议后逐项填写地址、端口、密码 / UUID，以及 TLS / Reality、传输方式（TCP / WebSocket / gRPC）等参数。支持 Shadowsocks、VLESS、VMess、Trojan、Hysteria2、TUIC v5、AnyTLS、SOCKS5，UUID 可以一键生成。添加后和粘贴链接导入的节点一样，可以对接中转、放进订阅，见 [手动填写](./guide/import.md#手动填写)
- **节点标签**：节点多了可以打标签区分，比如“出站”“落地”“香港”。点击节点 → **标签** 就能添加，导入和手动填写时也可以直接填；批量操作里能一次给多个节点设置标签。列表上方可以按标签筛选，搜索框也能搜标签。导入的节点和面板自建的入站都能打标签。标签只用来在面板里区分，不影响订阅，见 [标签](./guide/import.md#标签)

## 3.3.43

2026-10-26

- **服务器一键自动调优**：调优不用再手填带宽和延迟。点 **自动调优** 后，节点会自动挑一个公共 iperf3 测速点实测出口带宽，按带宽和内存算好缓冲区并应用，再验证单连接和多连接的速度。任务在后台运行，可以看进度和日志、随时停止，也能一键恢复原配置，见 [服务器调优](./guide/agent.md#服务器调优)
- **深度优化（可选）**：自动调优完成后，可以进一步扫描线路的限速拐点，找到后在出口加整形，减少丢包和重传。开始前会显示预计用掉的流量，确认后才执行；只有扫描结果可靠、验证通过才保留整形，否则恢复原来的队列配置，见 [深度优化](./guide/agent.md#深度优化)
- **按服务器设置通知**：在 **服务器 → 编辑 → 通知设置** 里，可以给每台服务器单独设置掉线 / 恢复、节点连通性、延迟 / 丢包、回程变化、内核错误、到期提醒这几类通知：跟随全局、开启或关闭。比如不想收某台服务器的延迟告警，把它的 **延迟 / 丢包异常** 关掉就行，检测和图表照常保留，见 [按服务器设置](./guide/notify.md#按服务器设置)
- **订阅源节点改名后不再变回去**：以前给订阅源导入的节点改名，下次更新订阅又会变回原名；现在会保留你起的名字
- **升级**：自动调优和深度优化需要把节点 agent 升级到 3.3.43 及以上；旧 agent 会提示升级

## 3.3.42

2026-10-24

- **备份可以上传到 GitHub Gist**：设置 → 备份与恢复 里填 GitHub 令牌，就能把备份存到自己的私密 Gist，可以立即上传，也可以每 6 / 12 小时、每天、每周自动上传（内容没变时跳过）；可选加密密码，填了就先加密再上传。恢复时从最近 10 个版本里选一个。上传失败可以在通知里提醒，见 [备份与恢复](./guide/backup.md#上传到-github-gist)
- **服务器调优按带宽和延迟计算**：调优里填服务器的带宽和主要线路延迟，缓冲区上限按「带宽 × 延迟 × 2 + 2MB」算，并按内存限定（单连接最多用内存的 1/32，另外按内存设 TCP 总内存上限），小内存机器不会被连接占满、大带宽机器也能跑满；连接起始缓冲区改为 1MB。同时去掉了在低核数机器上压吞吐的 `tcp_notsent_lowat`，加上更快回收连接、中转出站端口范围扩大到 10000–65535，BBR 模块开机自动加载。参考了 [tcpfit](https://github.com/Kylin010/tcpfit)，见 [服务器调优](./guide/agent.md#服务器调优)
- **升级**：按带宽和延迟调优需要把节点 agent 升级到 3.3.42 及以上；旧 agent 照常用原来的固定值

## 3.3.41

2026-10-24

- **打开面板更快**：图表组件改成用到时才下载（概览、服务器、节点、中转、订阅这些页面平时不显示图表），第一次打开面板要下载的脚本少了约三成
- **页面出错不再白屏**：某个页面出错或代码文件下载失败时，显示原因和「重新加载」按钮，侧栏 / 底栏照常能用，切到别的页面就恢复；刚升级完旧页面文件找不到时会自动刷新一次
- **更多页面回来时立即显示**：用户（含分组、限速）、转发、隧道、我的订阅也和概览等页面一样，第二次进入直接显示上次的内容、后台刷新；转发页的数据改成一次并行加载，不再分三轮等待
- **页面代码提前下载**：登录后浏览器空闲时，主要页面的代码在后台下载好，第一次进入也不用等（开了省流量模式时不预载）
- **加载太久有提示**：页面 10 秒还没加载完时提示可能是网络或面板的问题，并给出「重新加载」按钮

## 3.3.40

2026-10-24

- **撤回 Shadowsocks 2022 多用户**：3.3.39 加的「每个订阅单独的密钥（统计流量）」打开后节点连不上，先移除。打开过的入站升级后自动恢复成原来的单一密钥，面板会把配置重新下发到服务器；客户端里更新一下订阅即可，手动导入的要重新复制链接。Shadowsocks 订阅照旧共用凭据、不单独统计流量
- **切换页面更快**：以前每次切换都要等上一页的退出动画（约 0.3 秒）放完才开始加载新页面，侧栏 / 底栏也整个重建一遍；现在新页面立即开始加载，布局保持不动
- **回到看过的页面立即显示**：概览、服务器、节点、中转、订阅这几页，第二次进入时直接显示上次的内容，同时在后台刷新，不再出现「正在加载」
- 节点页的「全部服务器」筛选不再超出边框：箭头在框内，服务器名太长时显示省略号，手机上也不再把搜索框挤没

## 3.3.39

2026-10-23

- **Shadowsocks 2022 多用户**：加密方式是 2022-blake3-aes-128-gcm / 256-gcm 的入站，可以打开 **每个订阅单独的密钥（统计流量）**，每个订阅单独统计流量、设上限，停用或到期后单独断开。打开后原来的分享链接和已导入的配置会失效，订阅在客户端里更新一下即可，见 [Shadowsocks 多用户](./guide/nodes.md#shadowsocks-多用户)
- **ACME 证书的入站不再拒绝 mihomo 等客户端**：用 ACME 自动申请证书（没配 DNS 验证）的 sing-box 入站，以前带指纹的客户端（mihomo / OpenWrt Nikki 等）握手会报 `no application protocol` 超时，Surge 却能连；现在默认带上 h2 / http/1.1 ALPN
- **订阅失效时客户端能看到原因**：停用、到期或流量用完后，订阅链接不再报错，而是返回一个写明原因的节点（「⚠️ 订阅已过期，请联系管理员」等），对方更新订阅后在客户端里就能看到；原来的节点和凭据不会下发
- **在节点列表显示到期和流量**：订阅「基本」里的新开关，节点列表最前面多两个占位节点，显示到期日期和剩余流量，给不显示订阅信息的手机客户端看，见 [凭据、到期与流量](./guide/subscription-users.md)
- **订阅源可以设置 User-Agent**：有的机场按 UA 决定返回的格式或节点，拿不到节点或缺节点时可以换成客户端的 UA，见 [节点组与订阅源](./guide/subscription-sources.md#订阅源)
- **Stash / Shadowrocket 用模板时，分组收节点和 Mihomo 一致**：支持 `(?!...)` 这类断言（以前「其他地区」这种写法会收进全部节点）、`exclude-type`，以及 YAML 锚点 `<<: *xxx` 继承来的设置（以前这样的组没有节点，Stash 会报错）
- **注意**：订阅源、网址模板和图标库默认不能再从本机或局域网地址（127.0.0.1、192.168.x 等）下载。同机或局域网里跑着 Sub-Store 这类服务的，升级后在 **设置 → 安全与登录** 打开 **拉取订阅可访问内网地址**
