# 分流规则与链式代理

都在编辑订阅的 **规则** 页设置，影响客户端拿到的配置。想完全按自己的规则和策略组来，见 [订阅模板](./subscription-templates.md)。

## 分流规则

默认生成的配置只有“局域网直连、其余走节点选择”两条规则。在订阅的 **分流规则** 里打开后，Clash（mihomo）、sing-box、Surge、Shadowrocket、Loon 和 Quantumult X 的配置会带上：

- **基础规则**：局域网和国内域名 / IP 走“全球直连”，境外网站走“节点选择”，剩下的走“漏网之鱼”
- **勾选的分组**：每组是一个可单独选节点的策略组

| 分组 | 默认 | 包含 |
|------|------|------|
| 广告拦截 | 拦截 | 常见广告域名（sing-box 里直接拦截，没有可切换的组） |
| AI 服务 | 美国地区组 | OpenAI、Claude、Gemini 及其他境外 AI |
| YouTube | 节点选择 | YouTube |
| Netflix | 节点选择 | Netflix |
| 国外媒体 | 节点选择 | Disney+、Spotify、TikTok |
| Telegram | 节点选择 | Telegram |
| Google | 节点选择 | Google |
| 微软服务 | 直连 | 微软、OneDrive（GitHub 仍走节点选择） |
| 苹果服务 | 直连 | Apple |
| 游戏平台 | 直连 | Steam 等游戏平台（国内 CDN 始终直连） |

- 打开后自动按地区分组，每个分组都能直接选地区；没有美国节点时，AI 服务默认走节点选择
- Clash 和 sing-box 还会带上 DNS：国内域名用阿里 / 腾讯 DoH 解析，其余经节点用 Google / Cloudflare DoH 解析，避免 DNS 泄漏；Clash 另开启 fake-ip 和域名嗅探
- 规则集是 GitHub 上的远程文件，客户端定期自动更新：Clash 用 [MetaCubeX/meta-rules-dat](https://github.com/MetaCubeX/meta-rules-dat) 的 `.mrs`，sing-box 用同一仓库的 `.srs`，Surge、Shadowrocket、Loon、Quantumult X 用 [blackmatrix7/ios_rule_script](https://github.com/blackmatrix7/ios_rule_script) 里对应客户端的规则
- Clash 和 sing-box 经“节点选择”下载规则集，在国内也能下载；其余客户端自己下载规则集，网络连不上 GitHub 时规则会暂时缺失
- **Shadowrocket、Loon、Quantumult X 的节点订阅无法携带规则和策略组**，所以开启后这三个客户端的链接改为下发 **完整配置**（节点直接写在配置里），导入会替换 App 里原来的配置，原来作为节点订阅导入的需要重新导入：
  - Shadowrocket：Clash 格式的配置，点客户端直接导入（`shadowrocket://config/add/`）
  - Loon / Quantumult X：复制链接，在 App 的配置管理里“从 URL 下载”
  - 链式代理：Shadowrocket 照旧生成“落地（经 中转）”节点；Loon 和 Quantumult X 没有前置代理参数，落地节点仍是直连
- `.mrs` 只有 mihomo 内核能读：Stash 订阅的规则集改用 YAML 格式（同一套规则），也不带 mihomo 专用的 DNS / 嗅探设置；已停更的 Clash Premium / Clash for Windows 原版内核不支持

## 链式代理

让客户端先连 **中转节点**，再经它连 **落地节点**，网站看到的是落地节点的 IP。适合“国内 → 香港中转 → 美国落地”这类线路，或者给机场节点套一层自己的落地。

在编辑订阅的 **规则** 页展开 **链式代理**，先 **按来源** 设置，再 **按节点** 单独调整：

- **自建节点都作为落地**：面板上自己的节点（含它们的中转线路）都是出口
- **订阅源**：整个源点 **不用 / 落地 / 中转**。机场节点做前置时选“中转”，以后机场改名（比如倍率变了）、增删节点都会自动跟上，不用重新勾选。这里只列出订阅所选节点组里有节点的订阅源：链式代理只给组里的节点分配角色，不会再加节点进来，想用某个订阅源就先把它选进节点组
- **名称筛选**：订阅源设成落地或中转后，可以只用名称匹配的节点，写法和过滤一样：关键词用 `|` 分隔（如 `香港|日本`），或 `/正则/`（如 `/IEPL|IPLC/`）。按机场的原名匹配，机场改名、新增节点只要还匹配就自动跟上；没匹配上的节点不参与链式代理
- **没用上的节点不放进订阅**：链式代理里的订阅源，没筛选上或单独设成“不用”的节点直接不进订阅；不影响其他来源
- **中转节点不单独列出**：中转节点只出现在“中转节点”组里，不混进节点选择、自动选择和地区组（模板里取全部节点的组也会去掉它们）
- **按节点**：列表里是这个订阅所选节点组的所有节点，点 **不用 / 落地 / 中转** 单独设置，优先于来源设置；比如机场整个作中转，但把某个节点设成“不用”

订阅源的 [用途](./subscription-sources.md#订阅源) 设成“中转”或“落地”后，新建订阅会按用途自动设好上面这些。

角色的作用：

- **落地节点**：挂上中转组，即 Clash / Mihomo 的 `dialer-proxy`、sing-box 的 `detour`、Surge 的 `underlying-proxy`
- **中转节点**：放进“中转节点”组

生成的订阅里多两个分组：

| 分组 | 说明 |
|------|------|
| 落地节点 | 选出口，排在“节点选择”的第一个 |
| 中转节点 | 选中转，所有落地节点都经这里选中的节点连接 |

```yaml
proxies:
  - name: "美国 落地 01"
    type: vless
    # ...
    dialer-proxy: "中转节点"
```

- 落地和中转都至少选一个才生效；页面顶部会显示“已开启”
- 按节点设置记的是节点原名，之后改名、加国旗不影响；节点被删掉或改了原名需要重新勾选（按订阅源设置的不受影响）
- 旧版本用名称表达式设置的链式代理照常生效，页面上会提示；在列表里重新勾选后改用勾选结果
- 预览里会标出“落地”“中转”
- 落地节点仍可在“节点选择”和地区分组里直接选，选中后同样经中转连接；中转节点也可以单独使用
- 通用分享链接（Base64）无法表达链式，落地节点在里面是直连
- 延迟叠加，速度取决于最慢的一段；落地是 Hysteria2 / TUIC 等 UDP 协议时，中转节点要能转发 UDP

> 这是客户端侧的链式。想让服务器自己把流量转到另一个节点出去（客户端无感），用入站的 [分流与链式出站](./routing.md)。
