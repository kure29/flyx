# 凭据、到期与流量

订阅可以分给别人用：每个订阅有自己的凭据，可以设到期日期和流量上限，到期或用完自动断开。

## 独立凭据

- 每个订阅有自己的 UUID / 密码，和你的凭据同时写进节点配置，互不影响
- 可以设到期日期（到期当天 23:59 后断开）和流量上限，留空就是不限
- **停用**、**删除** 或 **到期** 后，面板会把它的凭据从服务器上删掉，已导入的配置也连不上了
- **重置链接和凭据**：旧链接和对方已导入的配置立即失效，适合链接泄露时使用
- 支持单独凭据的协议：VLESS、VMess、Trojan、Hysteria2、TUIC、AnyTLS、NaïveProxy、SOCKS5、HTTP，以及启用独立密码的 Xray Shadowsocks。未开启此选项的 Shadowsocks、Snell、WireGuard 和导入节点仍使用共用凭据；订阅停用后，客户端保存的配置仍能连接（界面标出“共用凭据”）。
- 3 天内到期会推送 [通知](./notify.md)

### Shadowsocks 独立密码

在 Xray 的 Shadowsocks 入站打开「每个订阅使用独立密码」，再把这个入站加入分发订阅使用的节点组。各订阅连接同一端口，使用不同的凭据，流量和限额分开计算。

- **传统 Shadowsocks**：支持 `aes-128-gcm`、`aes-256-gcm` 和 `chacha20-ietf-poly1305`，不要求客户端支持 SS2022。
- **SS2022**：支持 `2022-blake3-aes-128-gcm` 和 `2022-blake3-aes-256-gcm`；不支持 SS2022 ChaCha20 多用户。订阅会下发 `服务器密钥:用户密钥`，客户端必须支持 SS2022 多用户，仅支持普通 SS2022 的客户端可能无法连接。

该选项默认关闭。建议先在新端口测试；对现有入站开启时，旧共享密码不再生效，客户需刷新分发订阅。不提供不计量的共享链接，也不能把该入站选作 FLYX 的出站代理或分流出口，或与高级 JSON 配置同时使用。节点需要支持订阅流量计数；没有可计量的有效订阅时，该入站不监听。

## 流量上限

- 每个订阅单独统计流量（上传 + 下载），可以设 **流量上限**，用完自动断开，和到期一样
- **每月重置**：选每月几号，到那天 0 点自动清零；也可以在订阅详情里点 **重置流量** 手动清零，超限断开的会立即恢复
- 用到 90% 和用完时会推送 [通知](./notify.md)，概览页的“需要处理”里也会列出
- 客户端里能看到已用流量、总量和到期时间（`Subscription-Userinfo`）
- 有的手机客户端不显示上面这些信息：在订阅的 **基本** 里打开 **在节点列表显示到期和流量**，节点列表最前面会多两个占位节点，名字是「⏳ 到期 2026-12-31」和「📊 剩余 70.00GB / 100.00GB」（不限流量时显示已用）。它们连不上，只用来看
- 停用、到期或流量用完后，订阅链接不再报错，而是返回一份只有一个占位节点的配置，名字写明原因（「⚠️ 订阅已过期，请联系管理员」等），对方更新订阅后在客户端里就能看到；原来的节点和凭据不会下发
- 统计在节点所在的服务器上进行：每个订阅走自己的出站，服务器用 nftables 计数，Xray 和 sing-box 都支持。需要服务器上有 nftables，并且 agent 要和面板一起更新到最新版（旧 agent 能正常转发，只是不计数）
- 只统计支持单独凭据的节点。使用共用凭据的节点分不清是谁在用，不计入。

## 流量统计

订阅详情里切到 **流量统计**，可以按 **小时**（近 24 小时）、**日**（近 30 天）、**月**（近 12 个月）查看：

- 这段时间的下载、上传和合计
- 下载 / 上传折线图，点（或悬停）某个点看那个时间的流量
- 明细列表，最新的在前
- 图上的虚线是 **本周期起**：订阅创建或上次重置的时间

统计范围和流量上限一样，按查看者的时区分日、分月。新记录按 15 分钟汇总，可正确处理半小时、45 分钟时差；旧的小时记录跨本地时间边界时会按时长分配，并显示估算提示。**重置流量** 只清零已用量，不影响历史统计；历史保留约 13 个月，删除订阅时一起删除。3.3.29 起开始记录，之前的流量没有历史。

流量历史仍保留 400 天，以覆盖近 12 个月视图。持续有流量时，每个订阅每天的汇总记录由 24 条增至 96 条，约为原来的四倍，400 天约 38,400 条；仅有流量的时段会写入，实际表和索引占用取决于活跃订阅数量。升级前应预留相应数据库空间；监控明细的保留天数设置不影响订阅流量历史。

订阅上方的 **已用流量** 和这里的合计不一定相等：已用流量从本周期开始（创建或上次重置，详情里写着“X 起的上传 + 下载合计”）一直累计，这里只算所选的近 24 小时 / 30 天 / 12 个月。比如重置后已用量归零，近 30 天里仍有重置前的流量；3.3.29 之前用掉的流量算在已用量里，但图里没有。

## 在线 IP 限制与拉取记录

为了防止分享订阅被多人转传滥用，编辑订阅 → **基本 → IP 限制与防分享** 提供两层防护：

### 1. 跨节点同时在线 IP 上限

- **跨服务器合并统计**：节点端 `flyx-agent`（`3.10.3` 起）解析官方 Xray 与 sing-box 的连接日志，维护 120 秒滑动窗口并上报活跃客户端 IP；面板跨所有服务器合并去重，IPv6 自动按 `/64` 前缀合并，防止隐私地址轮换导致误判。
- **按需零开销**：Xray 默认支持；sing-box 仅在服务设置了在线 IP 上限的订阅时自动启用 `info` 日志级别，日常连接日志由 Agent 直接消费，不会刷满内核运行日志。
- **防误杀机制**：连续 **2 个采集周期** 均超过上限时才触发处理，同一轮多节点并行上报不重复计数，避免双栈或 Wi-Fi ↔ 5G 切换导致误杀。
- **三种超限动作**：
  - **仅告警**：通过 [通知](./notify.md) 推送超限告警与在线 IP 列表（30 分钟冷却），不断开连接。
  - **临时暂停**：从节点撤回该订阅凭据并暂停指定时长（默认 10 分钟），到期自动恢复，也可在订阅详情的 **IP 与记录** 页签点「立即恢复」手动解除。
  - **自动停用**：停用订阅并撤回节点凭据，直到管理员重新启用。
- **注意事项**：
  - 仅统计支持独立凭据的多用户协议（与按订阅计量流量相同）。
  - 节点需要升级到 `3.10.3` 及以上版本的 `flyx-agent`；未升级节点仍可正常转发，只是不上报在线 IP。
  - 中转场景下，需要在转发链路上开启 **PROXY Protocol** 才能向落地节点透传真实客户端 IP，否则落地看到的将是中转入口 IP。

### 2. 订阅拉取记录与 24h 拉取 IP 上限

- 面板自动记录每次 `GET /api/v1/open_api/sub/{token}` 拉取行为（客户端 IP、GeoIP 国家、User-Agent、输出格式及是否被拦截），每条订阅保留最近 200 条 / 7 天，可在订阅详情 → **IP 与记录** 查看。
- 设置 **24 小时拉取 IP 上限** 后，24 小时内超过不重复 IP 数量的新 IP 拉取订阅时会收到拦截提示节点（「⚠️ 订阅拉取 IP 数量超限，请联系管理员」），已放行的 IP 仍可正常更新订阅，且被拦截记录不会占用放行名额。
