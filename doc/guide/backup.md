# 备份与恢复

**设置 → 备份与恢复**：勾选数据类型导出为 JSON 文件，或从备份文件恢复所选类型。

## 数据类型

| 类型 | 包含 |
|------|------|
| 管理员账号 | 面板账号 |
| 服务器 | 服务器信息，包括单独设置的 [延迟测试点](./latency.md#给服务器单独设置) |
| 隧道 | 隧道 |
| 规则 | 转发规则 |
| 系统配置 | 设置页里的配置，包括延迟测试点 |
| 内核与入站 | 服务器上的内核、所有入站（包括导入的节点）、中转线路、流量统计基准，以及所有订阅（包括分享出去的） |

## 恢复

- 只恢复勾选的类型
- 恢复 **内核与入站** 后，面板会把内核配置重新推到在线的服务器，离线的服务器重连时自动补上
- 3.0.9 之前导出的备份不包含内核与入站，升级后请重新导出一次

## 上传到 GitHub Gist

同一页下方的 **上传到 GitHub Gist** 可以把备份存到你自己的 GitHub 私密 Gist，每次上传是这个 Gist 的一个新版本，GitHub 会保留历史版本：

- **GitHub 令牌**：在 GitHub → Settings → Developer settings → Personal access tokens 生成，只需要 **gist** 权限（Fine-grained 令牌选 Account permissions → Gists 读写）。保存时会先检查令牌能不能用，保存后不再显示；**清除令牌** 即停止上传
- **加密密码（可选）**：填了就先用它加密（scrypt + AES-256-GCM）再上传，恢复时要输入，忘记就无法恢复。留空则上传明文：私密 Gist 只是不公开列出，**拿到链接的人能看到节点密码、订阅凭据等信息**
- **自动上传**：关闭 / 每 6 小时 / 每 12 小时 / 每天 / 每周。内容和上次一样时跳过，不产生新版本；失败时按 [通知](./notify.md) 里勾选的「Gist 备份失败」提醒
- **立即上传**：第一次上传时自动新建私密 Gist；Gist 在 GitHub 上被删掉后，下次上传会新建一个
- **从 Gist 恢复**：选最近 10 个版本中的一个，加密的版本输入当时的密码，恢复全部数据类型（恢复前会先自动导出当前数据）。恢复用户后可能需要重新登录
- 令牌、密码和 Gist 设置不会写进备份，恢复备份也不会改动它们

## 不包含的内容

- Telegram Bot Token 和 Webhook 地址
- [通行证密钥](./passkey.md)：用 JSON 迁移后，用户需要用密码登录再重新绑定
- 延迟和监控的历史数据

需要连同这些一起备份，直接备份数据库：SQLite 是部署目录里的数据文件（更新面板时安装脚本会自动备份到 `backups/`），PostgreSQL 见 [PostgreSQL](./postgresql.md) 的“数据备份与恢复”。
