# 分流与链式出站

节点侧的分流和链式：客户端照常连这个节点，由它所在服务器的内核决定流量从哪里出去，客户端无感。想在客户端里组合“中转 → 落地”，见订阅的 [链式代理](./subscription-rules.md#链式代理)。

Xray 和 sing-box 内核支持，Snell 内核不支持（Snell 想用分流请改用 [sing-box 内置 Snell](./kernels.md#snell-用哪个内核)）。

## 设置

点入站 → **出站**，有三部分：

- **出站 IP 策略**：本机出去时用 IPv4 还是 IPv6，见下面的 [出站 IP 策略](#出站-ip-策略)
- **默认去向**：直连（从本服务器出去），或选另一个入站（其他服务器上的入站、导入的节点），流量再经它出去，网站看到的是它的 IP（链式代理）
- **分流规则**：按目标把一部分流量送到别处，从上到下匹配，先命中先生效，都不命中的走默认去向

每条分流规则选分类或填自定义域名 / IP，再选去向：**直连**、**阻断** 或某个出站节点。

## 分类

| 分类 | 内容 |
|------|------|
| 流媒体 | Netflix、Disney+、YouTube、HBO、Prime Video、Spotify、TikTok |
| AI | ChatGPT、Claude、Gemini |
| 常用 | Google、Telegram |
| 其他 | 广告、BT 下载、回国流量（中国大陆的域名和 IP） |

## 常见用法


- 只让 Netflix / ChatGPT 走有解锁 IP 的节点（例如导入的机场节点），其他流量照常直连
- 落地机阻断 BT 和回国流量，避免被投诉或滥用
- A → B → C 多级：给 A 的入站选 B 作为默认去向，再给 B 的入站选 C；每个节点只连下一跳
- 自定义域名包含子域名，例如填 `example.com` 也匹配 `www.example.com`

## 注意事项


- 分类数据自动更新：Xray 用 v2fly 的 geosite / geoip 数据，服务器每天检查一次，有新版本就下载、校验后替换并重启 Xray（启动失败会恢复原文件），内核日志里可以看到更新记录；sing-box 首次使用某个分类时下载规则集并缓存，之后每天更新。两者都经 **设置** 里的 GitHub 加速地址下载，落地机需要能访问
- Xray 能连接 VLESS / VMess / Trojan / Shadowsocks（不含插件和 ShadowTLS）/ SOCKS5 / HTTP 出站节点；Hysteria2、TUIC、AnyTLS 等请用 sing-box 内核；Snell 节点只有 sing-box 1.14 及以上能连接
- 出站节点是本面板的自签证书入站时，Xray 用证书指纹校验；导入的节点如果跳过了证书验证，Xray 无法连接（新版 Xray 已移除 `allowInsecure`），请改用 sing-box
- 开启了“获取真实客户端 IP”的入站只能经中转连接，不能作为出站节点；只监听本机的入站只能被同一服务器上的入站选用
- 出站节点开启了白名单时，会自动放行经它出站的服务器；规则之间形成循环（A 经 B、B 又经 A）时无法保存
- 被选作默认去向或分流去向的入站不能直接删除，需先解除；订阅源刷新时也会保留这些节点。出站节点如果随内核或服务器一起被删除，原本经它出去的流量会被丢弃（不会改为直连），请重新选择
- 用户流量统计照常按用户计算
- 保存会重启服务器内核，正在经这个节点连接的会断开一下重连。如果你正用这个节点打开面板，保存时连接会中断，面板会在节点恢复后自动确认是否已保存
- 新配置让内核启动失败时（例如下载分流规则集失败），服务器会自动恢复上一次能运行的配置并显示错误，不会因此掉线

## 出站 IP 策略

新建 / 编辑入站的**高级选项**，或入站的**出站**里，可设置“出站 IP 策略”：

- **自动（IPv4 / IPv6）**：沿用内核和系统的默认选择。
- **仅 IPv4 出站**：保持入站监听地址不变，域名只解析 IPv4；直接请求 IPv6 目标会被拒绝，不会回退到 IPv6。这样客户端仍可通过 IPv6 连到服务器，而本机的业务出站只走 IPv4。
- **仅 IPv6 出站**：保持入站监听地址不变，域名只解析 IPv6；直接请求 IPv4 目标会被拒绝，不会回退到 IPv4。客户端可通过 IPv4 或 IPv6 连到服务器，而本机的业务出站只走 IPv6。服务器必须具备可用的 IPv6 地址和路由，只支持 IPv4 的网站无法访问。
- **优先 IPv4（失败回退 IPv6）**：保留双栈解析，TCP 先尝试 IPv4；连接失败或约 250ms 内尚未连通时启动 IPv6 备用尝试，采用先成功的连接。域名没有 A 记录时直接尝试 IPv6。
- **优先 IPv6（失败回退 IPv4）**：与上面相反，TCP 先尝试 IPv6，失败或迟迟未连通时尝试 IPv4；域名没有 AAAA 记录时直接尝试 IPv4。

优先模式需要 Xray 25.6.8+ 或 sing-box 1.12+，直接指定 IPv4 / IPv6 地址时按该地址连接。UDP 按解析结果优先选择地址；因为 UDP 没有连接握手，远端静默不回包无法可靠判定故障，不会自动把同一数据包重放到另一种 IP。HTTP 错误状态和已经建立后断开的连接也不属于建立连接时的回退。

支持 Xray、sing-box 1.12 及以上（含 sing-box 内置 Snell），独立 Snell 内核不支持。策略按入站保存，编辑、重新下发和重启后仍生效。

指定非自动出站 IP 策略时，高级 JSON 不能覆盖 `tag` 或 `detour`，以免绕过按入站生效的策略；存在冲突会提示并拒绝保存。

直连分流和用户流量统计同样遵循策略。链式 / 代理分流连接下一跳时也遵循所选 IP 策略：仅 IPv4 需要 IPv4 地址或有 A 记录的域名，仅 IPv6 需要 IPv6 地址或有 AAAA 记录的域名；优先模式在下一跳使用域名时按优先级连接和回退。网站最终看到的出口由下一跳服务器决定，需要在最终落地上同样设置策略。

策略只管本机直接发出的连接：交给链式 / 代理分流下一跳的流量不按目标地址的 IP 类型拒绝，下一跳能访问什么由下一跳决定。下一跳是另一种 IP 的地址时保存会提示；之后下一跳地址变了导致不匹配时，只拒绝这个入站经过它的流量，同一服务器的其他入站照常工作。

## 分享地址

新建 / 编辑入站的**高级选项**里，**分享地址** 决定分享链接和订阅里客户端连接的地址，和监听地址、出站 IP 策略互不影响：

- **自动**：用所在服务器的 IP
- **服务器 IPv4 / 服务器 IPv6**：用服务器设置里对应的地址（服务器 IP 本身就是这种地址时也可选），服务器地址改了会跟着变。例如双栈服务器只想把 IPv6 发给客户端
- **自定义域名 / IP**：填一个域名或 IP，比如套了 CDN 的域名

链式代理的下一跳、端口连通性检测也用这个地址。**中转线路** 不用分享地址，仍连节点所在服务器的 IP：中转机不一定能连通客户端用的地址（比如只有 IPv4 的中转机连不上 IPv6）。
