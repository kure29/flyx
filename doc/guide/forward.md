# 转发规则与用户

面板保留了原来转发面板的功能：隧道、转发规则、多用户、配额与限速。只做落地 + 中转的话，用 [对接中转](./relay.md) 就够了，面板会自动建好需要的转发规则；需要自己管理端口转发或分给多个用户时再看这一页。

## 隧道

**中转 → 隧道**：从入口服务器到出口的转发线路，转发规则建在隧道上。

| 设置 | 说明 |
|------|------|
| 隧道类型 | **端口转发**：入口服务器直接转发到目标；**隧道转发**：入口经加密隧道到出口服务器，再由出口转发（入口和出口不能是同一台服务器） |
| 入口服务器 | 可以多选；多台服务器时可选 **负载策略** |
| 协议 | 隧道转发时入口和出口之间用的协议；只要中转、不需要加密时选 TCP |
| 流量计算 / 流量倍率 | 单向或双向计费，按倍率折算用户流量 |
| 转发引擎 | 端口转发时可选。**面板转发**（默认）：agent 直接转发；**realm**：入口服务器自动安装 [realm](https://github.com/zhboner/realm) 来跑这条隧道的转发 |

隧道卡片上的 **诊断** 可以检查入口到出口是否连通。

单向计算只扣除客户端上传到入口的流量；双向计算扣除上传与下载之和，再分别按流量倍率折算。该规则适用于面板转发、realm 和 nftables。监控图表仍展示实际上下行流量，因此可能与折算后的额度用量不同。修改计费方式只影响之后上报的流量，已累计的用量不会自动重新计算。

### realm 引擎

realm 是 Rust 写的端口转发程序，占用低，适合流量大的纯端口转发。选了 realm 的隧道：

- 入口服务器上的 realm 由面板安装和管理（**入站 → 内核** 里能看到“realm（转发引擎）”，可查看日志），agent 需要升级到支持 realm 的版本
- 转发规则照常建，TCP / UDP、多个目标负载（轮询或 IP 哈希，主备和随机按轮询处理）、Proxy Protocol 都支持；流量照常统计，配额、到期和暂停也照常生效
- **不支持** 限速、最大连接数和每 IP 限制，设置了也不生效
- 不能用于 nftables 模式服务器和远程服务器

随时可以在编辑隧道时切换引擎，面板会把已有的转发规则迁移过去。

## 转发规则

**规则** 页（或 **中转 → 规则**）：把入口端口收到的流量经隧道转发到目标地址。

- 选 **所属隧道**，填 **落地地址**（目标地址和端口），入口端口留空自动分配
- 支持 TCP / UDP
- 高级设置里可以开启 **Proxy Protocol 发送 / 接收**，让目标看到客户端真实 IP
- 可以限制 **最大连接数**、**每 IP 最大连接数** 和 **每 IP 限速**
- 支持批量导入导出

## 用户

**用户** 页：面板账号，管理员给用户分配隧道权限、流量和到期时间。

日、月配额触发后，暂停失败会继续重试；配额恢复后，恢复失败也会保留待办。节点未确认前，规则状态不会显示操作成功。用户手动暂停的规则不会被配额恢复自动开启。nftables 暂停会同时阻断已建立连接与新流量，恢复不会清空 NAT 计数器。 已确认的暂停每小时复核，节点重连后会重新确认。

- **流量限制**、**到期时间**、**流量重置日期**：用完或到期后停止转发，可以每月自动重置
- 给用户分配隧道时可选 **限速规则**
- 普通用户登录后只能看到分给自己的隧道，在上面建自己的转发规则
- 还可以把 [订阅分配给用户](./subscription-users.md#分配给面板用户)，用户在自己的面板里导入客户端、看流量和到期

## 限速与分组

- **限速** 页：定义带宽上限，分配隧道权限时可选
- **分组** 页：把隧道和用户编组，再按组授予隧道使用权限，用户多时不用逐个分配

## 监控

监控已并入 **服务器** 和 **中转**：

- **服务器** 列表（和卡片）上直接显示每台服务器的 CPU、内存、磁盘、实时网速和本月流量；点服务器再点 **监控**，看这台服务器的历史曲线和服务监控。本月流量从升级到这个版本后开始累计，按浏览器所在时区从每月 1 号算起
- **中转 → 质量**：隧道的延迟和丢包
- 普通用户有监控权限时，侧边栏仍有 **监控** 页

数据保留天数在 **设置 → 服务器与监控** 里设置。服务器到各地运营商的延迟见 [延迟与回程](./latency.md)。

## 共享

**共享** 页：把本地服务器分享给其他 FLYX 面板，或导入别人分享的服务器，两个面板可以互相使用对方的服务器做转发。
